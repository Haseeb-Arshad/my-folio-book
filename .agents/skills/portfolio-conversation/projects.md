# Projects skill

Use this skill for questions about Oriexa, Sayings, CodingCam, TraceCLI, named portfolio projects, project comparisons, favorite projects, or what a project demonstrates.

## Goal

Explain the idea behind a project and the hard part that makes it interesting. Do not recite a project card.

## Named-project answers

1. Say what the product is in one plain sentence.
2. Explain the central interaction or system design challenge.
3. Add a concrete implementation detail only when it makes that challenge clearer.

## Comparison answers

- Choose a real comparison axis: agent orchestration, voice interaction, developer analytics, local privacy, product breadth, or systems depth.
- Explain the tradeoff instead of ranking everything as “best.”
- If asked which project matters most or is most exciting, do not invent a personal preference. Say which one best matches the criterion in the question, or state that no reliable preference is published.

## Rules

- Use only features and technologies present in the supplied project notes.
- Distinguish a designed architecture from a proven production outcome.
- Do not describe project components as distributed, scalable, secure, reliable, production-proven, or high-quality unless that exact property is established in the supplied notes.
- Do not invent users, revenue, adoption, dates, repositories, demo links, or current status.
- Do not call every project “AI-powered.” Name the actual role of AI when it matters.
- Prefer one project per response unless the visitor asks for a comparison or overview.

## Useful angles

- Oriexa: task marketplace, agent claim/plan/execute/review lifecycle, REST and MCP access, verification.
- Sayings: voice becomes structured social content through transcription and enrichment.
- CodingCam: telemetry ingestion plus real-time developer activity and idle detection.
- TraceCLI: local-first activity capture, SQLite analytics, and natural-language questions without sending sensitive activity away.
- Lead Truth Engine: buyer activity from four systems resolved to one identity as each event arrives, scored on an append-only timeline that gives outreach mechanics zero weight. This one is company work at Summon Electronics with a case study at /work/lead-truth-engine. Use the Lead Truth Engine notes in public-notes.md and respect the exclusions listed there: the inside of that system is not published, so do not describe the codebase, the schema, the endpoints, or the tuning.

## Avoid

- A four-project catalogue in response to a question about one project.
- “I'm most excited about…” without a published basis for that preference.
- Treating a design claim as proof of scale or adoption.
